# Client-tg

Telegram Desktop для Windows со встроенным [TG WS Proxy](https://github.com/Flowseal/tg-ws-proxy) и автообновлениями.

- **Прокси встроен.** Telegram сам запускает TG WS Proxy в фоне, отдельно ничего ставить не нужно.
- **Включение в один клик.** Внизу списка чатов есть круглая кнопка со щитом, как у прокси в самом Telegram. Синий щит означает, что прокси включён, серый — выключен. При первом запуске прокси включён, чтобы можно было войти в аккаунт.
- **Обновления сами.** Каждые 3 часа GitHub Actions проверяет новые релизы [Telegram Desktop](https://github.com/telegramdesktop/tdesktop) и [TG WS Proxy](https://github.com/Flowseal/tg-ws-proxy). Если что-то вышло, собирается и публикуется новый релиз. Установленный клиент сам скачивает его: прокси обновляется сразу, а Telegram предлагает перезапуститься.

- **Моды.** Встроен движок модов в духе Forge/NeoForge: моды лежат в папке `mods`, у каждого есть `mod.json`, зависимости, свои команды, пункты меню и подписки на события. Список модов открывается из главного меню, пункт «Моды». Подробности в [docs/modding.md](docs/modding.md).

## Установка

1. Откройте [последний релиз](../../releases/latest) и скачайте `Client-tg-windows-x64.zip`.
2. Распакуйте в любую папку, куда у вас есть права на запись (например, `C:\Users\<вы>\Client-tg`, но не `Program Files`).
3. Запустите `Telegram.exe`.

Данные Telegram хранятся рядом с `Telegram.exe` (портативный режим), поэтому клиент не мешает обычному Telegram Desktop, если он тоже установлен. Прокси слушает `127.0.0.1:1444`, чтобы не конфликтовать с отдельным TG WS Proxy на 1443.

## Как это устроено

```
client/            изменения Telegram Desktop
  apply.py         встраивает их в исходники tdesktop перед сборкой
  src/tgws/        кнопка на главном экране и запуск прокси
  src/modengine/   движок модов: загрузчик, шина событий, хуки, окно «Моды»
modapi/include/tgmod/  API для авторов модов (tgmod.h и tgmod.hpp)
examples/mods/hello/   пример мода
sidecar/           TgWsProxy.exe: прокси Flowseal без трея + автообновление
  tgws_sidecar.py  точка входа
  tgws_updater.py  скачивает и устанавливает новые версии
scripts/
  plan.py          решает, что пересобирать
  make_release.py  собирает zip и manifest.json для обновлений
.github/workflows/build.yml   проверка апстрима, сборка, релиз
```

Изменения Telegram накладываются не патчем, а вставкой нескольких строк по устойчивым якорям, поэтому обычные обновления tdesktop собираются без ручной работы. Если апстрим всё же изменит нужное место, сборка остановится и откроет issue, а пользователи останутся на последней рабочей версии.

Обновление на компьютере: `TgWsProxy.exe` раз в 3 часа читает `manifest.json` последнего релиза, скачивает изменившиеся файлы и проверяет SHA-256. Работающий `Telegram.exe` переименовывается в `Telegram.exe.old`, новый встаёт на его место и запускается при следующем старте. Новый `TgWsProxy.exe` подменяется самим Telegram сразу после выхода старого.

## Настройки репозитория (необязательно)

- `TG_API_ID` и `TG_API_HASH` в Settings → Secrets → Actions: свои ключи с [my.telegram.org](https://my.telegram.org). Без них используются открытые ключи, которыми tdesktop собирает свои CI-сборки.
- Запустить сборку вручную: Actions → Build & release → Run workflow (галочка `force` пересоберёт всё).
